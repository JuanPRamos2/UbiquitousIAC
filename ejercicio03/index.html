Abrir WSDL

1 Objetivo

Diseñar y documentar un servicio SOAP que permita trabajar con conceptos del catálogo de la librería mediante mensajes XML y un contrato WSDL.

  • Consultar conceptos pendientes.
  • Registrar clasificaciones IaaS, PaaS, SaaS y FaaS.
  • Consultar el progreso de clasificación.
  • Obtener estadísticas por modelo.
  • Manejar respuestas correctas y SOAP Faults.
  • Consumir el servicio desde más de un cliente.

2 Arquitectura general

La solución separa claramente al cliente de escritorio del servicio SOAP. La comunicación se realiza mediante HTTP y mensajes XML definidos por el contrato.

Usuario → Aplicación de escritorio → HTTP / XML → Servicio SOAP
                                           ↓
                                      Respuesta XML

3 Contrato WSDL y tipos XSD

El contrato del servicio se encuentra en library-classifier.wsdl y define las operaciones, mensajes y tipos utilizados por los clientes.

Se utiliza el estilo document/literal wrapped y el namespace http://udem.edu.mx/iac/library-classifier.

Entre los tipos principales se encuentran identificadores numéricos, textos y la enumeración CloudModelo: IaaS, PaaS, SaaS y FaaS.

4 Operaciones SOAP

ObtenerConceptosPendientes Consulta los conceptos que todavía deben ser clasificados.
RegistrarClasificacion Registra la categoría Cloud seleccionada para un concepto.
ObtenerProgresoUsuario Devuelve el avance general de clasificación.
ObtenerEstadisticasPorModelo Resume los registros por IaaS, PaaS, SaaS y FaaS.

5 SOAP Request, Response y Fault

El ejercicio incluye ejemplos de solicitudes correctas, respuestas y errores controlados.

  • Request RegistrarClasificacion
  • Response de registro
  • Ejemplo de SOAP Fault
  • Request de estadísticas
<soap:Fault>
  <faultcode>soap:Client</faultcode>
  <faultstring>El concepto ya fue clasificado por este usuario</faultstring>
  <detail>...</detail>
</soap:Fault>

El SOAP Fault permite comunicar un error al cliente de forma estructurada y sin mostrar detalles internos de implementación.

6 Aplicación de escritorio

La aplicación de escritorio funciona como cliente del servicio SOAP y permite completar el flujo de clasificación desde una interfaz gráfica.

  • Captura nombre, apellidos y correo.
  • Consulta conceptos pendientes.
  • Clasifica definiciones como IaaS, PaaS, SaaS o FaaS.
  • Envía la clasificación mediante SOAP.
  • Muestra respuestas y errores de manera entendible para el usuario.

Documentación del cliente: README_DESKTOP.md.

9 Métricas SOAP vs REST

Como parte del análisis se comparó el tamaño de un mensaje SOAP con un payload equivalente en JSON.

Request SOAP623 bytes
Payload equivalente en JSON164 bytes
Estructura XML vs datos~74 % / ~26 %

SOAP utiliza más estructura, pero a cambio ofrece un contrato formal y mensajes estandarizados.

11 Conclusiones

El ejercicio permitió comprender cómo SOAP estructura la comunicación entre aplicaciones mediante XML, WSDL, tipos XSD y SOAP Faults.

La principal diferencia frente a una API más ligera es la cantidad de estructura necesaria. Aun así, el contrato formal facilita que diferentes clientes entiendan exactamente qué operaciones existen, qué datos reciben y qué respuestas deben esperar.
